# A2b · Input-level re-embed **fidelity** scope (paired cache-linear vs re-embedded)

**Status: SCOPE ONLY. No run started. Feasibility / fidelity PR, not a production-detector PR.**

Branch: `analysis/input-level-reembed-fidelity-a2b`. This document designs the
**smallest paired experiment** that can answer one question and nothing more:

> Does the false-collapse / support-breadth / two-axis abstention structure
> (#82→#88) survive when drift is generated by **input-level image
> interpolation followed by a fresh DINOv2 re-embed**, instead of the current
> **cache-level linear convex blend** between stored embeddings — or is some
> part of the signal an artifact of moving linearly through embedding space?

It does **not** propose changing retrieval, `forward()`, `associative_core.py`,
or the detector. It does **not** start a full run.

---

## 1. The enabler: the cache-linear drift is already a chord between two *real* images

From `benchmarks/probe_contraction.py::VisionDriftStream` (verified):

```python
# endpoints are BOTH real cached features (unit-normalized):
embeds = F.normalize(embeds, dim=-1)              # all cached DINOv2 features -> unit
self.attractor_feats = embeds[aidx]              # (A, D) real attractor-class features
self._train_assign = torch.randint(0, A, (n,), generator=rng)   # sample i -> ONE real attractor feat

def _blend(self, X, assign, c):
    a = self.attractor_feats[assign]             # the assigned real attractor feature
    mixed = (1.0 - c) * X + c * a                # convex blend between two REAL endpoints
    return F.normalize(mixed, dim=-1)
```

So today's drift is **not** sample→class-centroid; it is `embed(image_X)` →
`embed(image_A)` for two specific real images, with a deterministic per-sample
assignment fixed across epochs. The class's own docstring names this exact PR as
the open follow-up:

> *"drift here is a LINEAR convex blend in feature space between two real
> endpoints … input-level (pixel/patch) re-embedding is a future faithfulness
> check."*

**Consequence:** a faithful input-level counterpart with **identical endpoints**
is directly constructible. For the same image pair `(X_img, A_img)`:

| arm | trajectory at contraction `c` |
|-----|-------------------------------|
| **cache-linear** (existing) | `q(c)  = normalize( (1−c)·embed(X_img) + c·embed(A_img) )` |
| **input-level** (new)       | `q'(c) = normalize( embed( pixelblend(X_img, A_img, c) ) )` |

At `c=0` both equal `embed(X_img)`; at `c=1` both equal `embed(A_img)`. **Only
the path between the shared endpoints differs** — which is precisely, and only,
the fidelity question.

## 2. Paired design (shared endpoints, single difference)

Two arms, everything else byte-identical:

1. **Cache-linear arm** = the *existing* `VisionDriftStream` driven by the
   *existing* `calibration_probe.py` loop. Re-using the exact `--vision-classes`,
   `--vision-attractor-class`, `--seed`, and the #87/#88 schedule
   (`--contraction-start 0.35 --contraction-end 0.9`, 30 epochs) means this arm
   **reproduces a known merged result bit-for-bit** — a free correctness anchor.

2. **Input-level arm** = a new `ReembedDriftStream` that:
   - **reuses the identical sample/attractor selection and per-sample assignment**
     as `VisionDriftStream` (same seed → same `tr`/`ho` indices, same `aidx`, same
     `_train_assign`/`_held_assign`), so endpoints + pairings match exactly;
   - maps each selected cached row back to its **source image** (see §5 gate);
   - at each epoch's `c`, returns `embed( pixelblend(X_img, A_img, c) )` via a live
     DINOv2 ViT-L/14 forward, fed to the **same engine/probe/floor/vote**.

Both arms emit the **same `per_probe.csv` schema** (`PER_PROBE_KEYS`), so
`benchmarks/analyze_calibration.py` and `benchmarks/heldout_abstention.py` run
**unchanged** on both — the detector, held-out splits (parity / contiguous), and
two-axis AUC logic are reused as-is, never modified.

### Input-level operator
- **Primary: pixel cross-fade** — `img(c) = (1−c)·X_img + c·A_img` on the
  ToTensor'd `[0,1]` tensors, *then* the cache's own
  `Resize(224,BICUBIC)→CenterCrop(224)→Normalize`, *then* encode. This is the
  faithful "same convex operation, different space (pixels vs embeddings)"
  contrast. It is the whole minimal experiment.
- **Secondary (optional, NOT in the pilot): perturbation drift** — increasing
  corruption severity (blur/noise) of `X_img` alone, re-embedded. Adds a second
  drift driver but also a second variable; defer until the cross-fade result is
  in.

## 3. Subset sizing (smallest that still shows a forced zone)

Re-embed cost = `n_samples × n_epochs` DINOv2 forwards — trivial, so the limit is
"smallest that still produces a forced zone," not compute.

**Pilot (de-risk plumbing first — §5):** 1 class + 1 attractor, ~8 samples,
~6 contraction values. Goal is *only* to validate the feasibility gates, not
signatures.

**Subset run (after the pilot passes):**
- **3 classes + 1 attractor** (one fewer class than #87/#88's four — enough to
  form the forced zone, fewer re-embeds). Reuse three of the merged run's class
  ids + its attractor for direct comparability.
- **32 train + 64 held-out per class** (matches #87/#88; held-out only grows
  calibration sample size).
- **Schedule identical to #87/#88** (`0.35→0.9`, 30 epochs) so the cache-linear
  arm reproduces the merged numbers and the re-embed arm is sampled at the *same*
  `c` values.
- **Fixed `--seed 0`**, both arms, single dataset.
- **Dataset: ImageNet-R / DINOv2 ViT-L/14** for the pilot+subset. This is the
  better-anchored choice once the extractors are inspected (see §5 G0):
  - its extractor (`extract_imagenet_r_vitl14.py`) is **in-repo**, so the build
    transform + split are known and reproducible;
  - it is **ViT-L/14**, matching #87/#88 (so the cache-linear arm reproduces the
    merged #88 numbers — a free anchor);
  - #88 already characterized its forced zone.
  Cost: source-image recovery requires **replaying the seeded stratified split**
  (`SEED=42`, 80/20), not trivial indexing — deterministic and cheap (§5 G0).
  - **CIFAR-100 is deliberately NOT used here.** The in-repo CIFAR cache is
    ViT-**B**/14 (`extract_dinov2_vitb14.py`), a *different encoder* than #87/#88's
    ViT-L/14, so it would add an encoder variable; and **no `extract_cifar100_vitl14`
    exists in-repo**, so the #87 CIFAR ViT-L/14 cache's transform/order is not
    self-evident and can't anchor G1 without first establishing provenance.

## 4. Signatures to compare (constraint 3) — side-by-side, cache-linear vs re-embed

Tabulated exactly like the #88 CIFAR↔ImageNet-R table, **match or diverge** per row:
1. forced-zone concentration of errors (is 100% of error still in the forced bucket?);
2. false-collapse signature (forced-wrong = sharp top-1 / thin support / off-class?);
3. support-breadth orientation (still **+1**, broad = correct?);
4. `rank_gap` sign-flip (still inverts inside the forced zone?);
5. two-axis held-out AUC (`rank_gap + manifold_support`), parity & contiguous;
6. operating-point behavior (coverage / retained-acc / error-capture / false-abstain).

A signature "survives" if it reproduces in **direction and rough magnitude** on
the re-embed arm; "diverges" if direction flips or magnitude collapses.

## 5. Geometry diagnostics (constraint 4)

Computed per sample-trajectory in **unit-embedding space**, both arms:
- **Cosine path length** — arc length `Σ‖q(c_{k+1}) − q(c_k)‖` (and angular
  version) along each path; the linear chord is near-minimal, the re-embedded
  path is expected longer/curved.
- **Linear-vs-reembed deviation** — at each `c`, `1 − cos(q_linear(c), q_reembed(c))`
  and L2 gap; report the max and the `c*` where the manifold gap peaks (this is
  the "how off-manifold is the chord" curve).
- **support_breadth distribution shift** — compare `n_surviving_votes` /
  `effective_support` histograms between arms, overall and within the forced zone.
- **forced-zone onset shift** — the `c` (and epoch) at which the forced bucket
  appears and accuracy collapses, per arm; does re-embedding move the onset?

### Feasibility gates — the pilot must pass these *before* the subset run
- **G0 source-image recovery.** Confirm each cached row maps to a retrievable
  source image. The cache stores only `{"embeds":(N,D),"labels":(N)}` — **no
  index/path column** — so recovery depends on reproducing the extractor's
  ordering exactly:
  - **ImageNet-R (`extract_imagenet_r_vitl14.py`, chosen):** the `*_train.pt`
    cache is the `extract()` pass over `train_ds = stratified_split(ImageFolder,
    0.8, SEED=42)` with `shuffle=False`. So cache row `i` ↔ `ImageFolder` sample
    `train_indices[i]`, where `train_indices` is regenerated by **replaying
    `stratified_split` with `SEED=42`** (deterministic; `ImageFolder.samples[idx]`
    then gives the image path). This is the recovery mechanism the new stream
    must implement. ← highest-value gate.
  - The build transform is fixed and known
    (`Resize(224,BICUBIC)→CenterCrop(224)→ToTensor→Normalize(IMAGENET mean/std)`),
    enabling the G1 identity check below.
  - **Risk:** if the installed `torchvision`/`ImageFolder` class ordering or the
    `torch.randperm` stream differs from build time, `train_indices` won't match
    and recovery fails silently — G1 is the guard that catches this.
- **G1 c=0 / c=1 endpoint identity.** `embed(transform(X_img))` must reproduce the
  cached unit feature `X` (cosine > 0.999), and likewise for the attractor image
  vs `a`. This proves the two arms truly share endpoints and that the cache
  transform is reproduced exactly. If it fails, the arms aren't comparable.
- **G2 paths actually diverge.** Mid-path deviation (§5) must be non-trivially
  `> 0`, else there's nothing to study.

  duplicated. Same `per_probe.csv` schema → existing analysis scripts unchanged.

## 8. Open decisions to confirm before building
1. **G0 recovery mechanism** — implement + verify the ImageNet-R
   `stratified_split(SEED=42)` replay → `ImageFolder` path mapping (§5 G0). If the
   replay can't be made to match (torchvision/randperm drift), fall back to
   writing a *new* cache that stores explicit source indices/paths — never edit
   the merged cache or extractor.
2. **Normalization parity** — feed the re-embed arm's raw DINOv2 output to the

   normalizes internally); only unit-normalize for the geometry diagnostics.
3. **Pixel-blend domain** — blend on `[0,1]` ToTensor images before Normalize
   (above); confirm this is the intended convex pixel operation.
4. **Class/attractor reuse** — carry over 3 of #88's ImageNet-R classes
   `{166,63,77,156}` + attractor `134` for direct comparability against the
   merged forced-zone characterization.
